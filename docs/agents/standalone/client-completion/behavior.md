# Bash completion behavior

Part of [Standalone: client completion](../client-completion.md). This page defines the candidates offered by `kerghan completion bash`, the positions where they appear, what is deliberately never completed, and the behavioral test matrix. Product edge-case numbers are from epic #424.

## Registration and spacing

The script defines `_kerghan` (helpers, if any, use the `_kerghan_` prefix) and registers it as:

```bash
complete -o nospace -F _kerghan kerghan
```

`-o nospace` is the only permitted option: there is no default, bashdefault or filename fallback. Bash 3.2 has no `compopt`, so `_kerghan` includes a trailing space in each candidate except `KEY=` candidates. This lets a value follow a key immediately, while commands, flags, fixed values and bare `--unset` keys get a space. The function itself owns that spacing even when only one candidate remains.

## Completed words

The word lists follow `standalone/bin/kerghan`.

### Top level and commands

Top level offers `up`, `down`, `logs`, `status`, `compose`, `reset`, `update`, `update-env`, `configure`, `wizard`, `version`, `completion`, `help`, `-h` and `--help`. `help` aliases are top-level only.

| Command | Candidates |
|---------|------------|
| `up` | `--offline`, `-p`, `--port`, `--auto-login`, `--no-auto-login`, `--bind`, `-f` |
| `logs` | `-f` |
| `update` | `--force`, `--yes`, `--restart`, `--no-restart` |
| `wizard` | `--advanced` |
| `completion` | `bash` as its first argument only |
| `configure` | flags and setting keys below |
| `down`, `status`, `compose`, `reset`, `update-env`, `version`, `help` | nothing |

Flags already on the line are removed from suggestions. Aliases count as one option (`-p` and `--port`), and mutually exclusive pairs are treated as one choice (`--auto-login`/`--no-auto-login` and `--restart`/`--no-restart`). `configure --unset` may repeat. The hidden `update --finish` step is accepted by the client but excluded from completion.

### `configure` lists

`configure` accepts `--show-secrets`, `--force`, `--unset KEY`, `KEY=VALUE`, `KEY=-`, and a bare key for reading one setting. Completion offers:

- Flags `--show-secrets`, `--force` and `--unset`.
- Config keys with `=` attached: `port=`, `variant=`, `runtime=`, `stop-timeout=`, `image-tag=`, `auto-login=`, `bind=`, `restart-on-update=`.
- Static env keys from the client's `DEFAULT_ENV_KEYS` plus `FRONTEND_BASE_URL`, also with `=` attached. The client-managed `KERGHAN_DEFAULT_USER_ALWAYS_AUTHENTICATED` and `KERGHAN_DEFAULT_USER_ALLOWED_IPS` are refused by `configure` and never offered.
- Fixed values after `KEY=`:

| Key | Values |
|-----|--------|
| `variant` | `online`, `offline` |
| `runtime` | `auto`, `sysbox`, `privileged` |
| `auto-login` | `true`, `false` |
| `restart-on-update` | `ask`, `always`, `never` |

After `--unset`, completion offers bare config keys and `FRONTEND_BASE_URL`, but not `DEFAULT_ENV_KEYS`, because those are regenerated by `up` and `update-env`. A key already supplied as `KEY=…` or after `--unset` is not offered again. `--show-secrets` suppresses other suggestions when active; `--force` suppresses `--show-secrets`; a write suppresses `--show-secrets`.

The config key, env key and fixed-value lists are generated from the client's constants. Commands and per-command flags are hand-written because the dispatch and parsers use `case` patterns; sync tests cross-check these against `kerghan help`. The `--unset` list is derived from generated lists. Every config key must be classified as free-form or have a fixed-value constant, never both or neither. The sync test documents `EXCLUDED_WORDS="--finish"` and `FREE_FORM_KEYS="port bind image-tag stop-timeout"` as intentional classifications.

Rejected alternatives: generating all commands/flags would require rewriting dispatch and parsers while retaining duplicate `case` patterns; hand-writing all lists would discard the consistency provided by existing constants.

## Per-position table

“On the line” means words after the command other than the word currently being completed. Candidates are filtered by the current prefix. Every candidate has a trailing space except `KEY=` candidates. “Nothing” means an empty `COMPREPLY` and no filename fallback. Labels are stable because tests cite them.

### Top level

| Label | Context | Candidates |
|-------|---------|------------|
| `top-first` | First word after `kerghan` | All top-level commands and help aliases listed above |
| `top-later` | Later word after unknown command or top-level help word | Nothing |

### Commands

| Label | Context | Candidates |
|-------|---------|------------|
| `up-flag-arg` | Previous word is `-p`, `--port` or `--bind` | Nothing; the argument is not parsed as a flag |
| `up-flags` | Other `up` positions | The `up` flags, less already-used flags; aliases and paired flags count together |
| `logs` | Any `logs` position | `-f` unless already on the line |
| `update` | Any `update` position | The `update` flags, less already-used flags; after a version, flags remain available; `--finish` is omitted |
| `wizard` | Any `wizard` position | `--advanced` unless already on the line |
| `completion-first` | First `completion` argument | `bash` |
| `completion-later` | Later `completion` argument | Nothing |
| `no-args` | `down`, `status`, `compose`, `reset`, `update-env`, `version`, `help` | Nothing |

For `up`, the word after `-p`, `--port` or `--bind` is an argument, never a flag. `compose` passes arguments through and has no completion; `logs` accepts only `-f`.

### `configure`

The source lists are the generated config keys, env keys and fixed values above. “Keys on the line” includes `KEY=…` (including `KEY=-`) and every key following `--unset`.

| Label | Context | Candidates |
|-------|---------|------------|
| `cfg-unset` | Previous word is `--unset` | Bare config keys and `FRONTEND_BASE_URL`, less keys already on the line; never a default env key |
| `cfg-value` | Current word is `KEY=` or `KEY=<partial>`, including bash's split form `KEY`, `=`, `<partial>`; key has fixed values | That key's fixed values, prefix-filtered |
| `cfg-free` | Current word is `KEY=…` for a free-form or env key, or `KEY=-` | Nothing |
| `cfg-show-secrets` | Other position while `--show-secrets` is active | Nothing |
| `cfg-other` | Other position | Eligible flags and all config/env keys as `KEY=`, less keys already on the line |

At `cfg-other`, `--show-secrets` is offered unless a write or `--force` is present; `--force` is offered unless already present; `--unset` is always offered. Bare keys for reading one setting are never suggested. A `KEY=-` still leaves other `KEY=` candidates available.

The default `COMP_WORDBREAKS` includes `=`. Completion reconstructs `KEY=VALUE` from `COMP_WORDS`/`COMP_CWORD`; it does not change `COMP_WORDBREAKS` or use bash-completion helpers. Immediately after `=`, bash may represent the cursor with `=` as the current word or with an empty word after `=`; both shapes work on bash 3.2 and 4+.

### Edge cases

The numbered behavior from epic #424 is retained:

1. Invocation through `./kerghan` or `~/.local/bin/kerghan` works.
2. An alias/symlink with another name such as `kg` is not registered automatically. Users may run `complete -o nospace -F _kerghan <name>`.
3. Bash 3.2 is supported: no `compopt`, associative arrays, `mapfile`/`readarray`, or bash-completion helper dependency.
4. Unknown command at a later position offers nothing.
5. Commands with no options remaining offer nothing.
6. `compose` passthrough and `logs` after `-f` offer nothing.
7. `update [VERSION]` never suggests versions, but flags remain available before or after a typed version.
8. Values for `up --bind`, `-p` and `--port` are free-form and do not become flags or keys.
9. Used flags are not repeated (except repeatable `configure --unset`); aliases count as one.
10. Either member of a paired flag suppresses both members.
11. Hidden `update --finish` is never suggested.
12. Help aliases are only offered at the top level.
13. Keys include `=` and fixed values work across bash's `=` word-break shapes.
14. `--unset` suggests bare unsettable keys, excluding default env keys.
15. Env key names are static; env values are not completed and env files are not read.
16. `KEY=-` and free-form values offer nothing.
17. Keys already on the line are not repeated.

The additional command-argument error cases (edge cases 18–19) are in [command behavior](command.md#error-cases-and-messages).

## Never completed

- Free-form config values (`port`, `bind`, `image-tag`, `stop-timeout`) and `-p`/`--port`/`--bind` arguments.
- `update` versions, which would require a network request.
- `compose` passthrough arguments; `logs` arguments other than its supported `-f`.
- Env values and the hidden `KEY=-` value.
- Hidden update steps such as `update --finish`.
- Filenames: no default completion or filename fallback is registered.

## Required behavior tests

`standalone/test/completion.bats` drives `_kerghan` with explicit `COMP_WORDS` and checks exact `COMPREPLY` sets, including significant trailing spaces. `complete_line` is used for whitespace-only inputs; `complete_words` is used for `=` shapes. Every matrix label and edge case has a named test, and the same suite runs under bash 5 and bash 3.2.

The matrix includes registration; all top-level and per-command rows; used aliases and exclusive flags; argument suppression; version and hidden-step behavior; `completion bash`; no-argument/passthrough cases; all `configure` fixed/free/env/unset shapes; and filenames not being offered. `completion_sync.bats` checks commands and flags from usage, setting keys from help, generated values against client constants, and free-form/fixed-value classification. `completion_safety.bats` verifies no config/env-file reads. See [Testing](testing.md) for the harness and suite setup.
