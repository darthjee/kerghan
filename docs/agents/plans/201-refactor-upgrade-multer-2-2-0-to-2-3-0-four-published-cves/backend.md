# Backend Plan: Refactor: Upgrade multer 2.2.0 to 2.3.0 (four published CVEs)

Main plan: [plan.md](plan.md)

## Implementation Steps

### Step 1 — Bump the `resolutions.multer` pin and regenerate the lockfile
`backend/package.json` already carries a yarn `resolutions` entry forcing `multer` to `2.2.0` — added specifically because `@nestjs/platform-express` declares its own internal `multer` dependency pinned to an exact version (true through the latest published `11.x` release, `11.2.5`; only `12.0.4` moves off it, which requires a Nest major upgrade out of scope here). There is no direct `multer` entry under `dependencies` to change.

Bump `resolutions.multer` from `"2.2.0"` to `"2.3.0"` (or a `"^2.3.0"` range), then regenerate the lockfile inside the container — never on the host:

```
docker-compose run --rm kerghan_tests yarn install
```

### Step 2 — Verify the vulnerable version is fully gone
- Grep the regenerated `backend/yarn.lock` for `multer@2.2.0` (or any resolution touching it) and confirm no entry remains anywhere, including nested under `@nestjs/platform-express`.
- Run `docker-compose run --rm kerghan_tests yarn lint` and `docker-compose run --rm kerghan_tests yarn coverage` — both must pass, with coverage not reduced.
- Mention in the PR description that the fix was a one-line bump to the existing `resolutions` override (not a new dependency or a `@nestjs/platform-express` upgrade).

## Files to Change
- `backend/package.json` — bump `resolutions.multer` from `2.2.0` to `2.3.0`.
- `backend/yarn.lock` — regenerated by `yarn install` inside the container to reflect the new resolution.
