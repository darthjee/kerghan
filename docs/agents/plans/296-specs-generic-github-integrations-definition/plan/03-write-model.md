# Write `integrations/model.md`

Create `docs/agents/specs/integrations/model.md` encoding storage model **A** (single
`integrations` table, opaque type-specific payloads):

- **Columns** — `id` (internal PK), `uuid` (exposed; generated by the application *before*
  encryption, because it is part of the AAD), `user_id` (FK → users, `ON DELETE CASCADE`),
  `provider`, `type`, `label`, `status`, `status_reason` (nullable), `github_login`
  (identity the credential belongs to), `expires_at` (nullable), `last_tested_at` (nullable),
  `last_test_result` (nullable), `metadata` (JSON, non-secret, type-defined shape),
  `secret_key_id`, `secret_iv`, `secret_auth_tag`, `secret_ciphertext`, `created_at`,
  `updated_at`. Give types/nullability for each, and say that the DB enforces only generic
  columns; types validate secret plaintext shape and `metadata` in code via `type-contract.md`.
- **Enumerations** — `provider`: `github`; `type`: `pat`, `oauth_app`, `github_app`;
  `last_test_result`: `success`, `status_changed`, `transient_error` (or equivalent; keep
  consistent with `api.md`).
- **Constraints** — label required, trimmed, 1–100 chars, unique per user case-insensitively
  (409 on duplicate; state how uniqueness is enforced, e.g. a normalized lower-cased column or a
  case-insensitive collation index on `(user_id, label)`); per-user cap from
  `KERGHAN_INTEGRATIONS_MAX_PER_USER` (default 20, read once at boot via
  `core/numeric-config.ts`).
- **Status lifecycle** — the four statuses table (`active`, `invalid`, `expired`,
  `undecryptable`), `status_reason` codes (generic `insufficient_permissions`; per-type codes
  defined by type specs), and every transition from the issue: create, replace credential,
  test connection, transient failures, decryption failure (including key-id mismatch), rename,
  future backend use (note only).
- **Expiry** — computed on read (`expires_at < now` ⇒ reported `expired`), persisted on the next
  test, no background job; "expiring soon" is a UI hint only (window fixed in `ui.md`).
- **Edge cases** — user deleted (cascade; per-type best-effort revocation), same identity twice
  for one user (allowed), same identity across users (allowed, isolated, never revealed),
  replace with a different identity (allowed, metadata refreshed), credential stops working (no
  polling), undecryptable rows (still listed; replace or delete allowed), concurrent edits (last
  write wins; deleted/foreign ⇒ 404), GitHub unreachable on create/test.
- **Lockout table** — the per-user failure cool-off state table (see `security.md`), mirroring
  the existing account-edit lockout table/entity shape.
- **Migrations** — additive only, each with a working `down`.
- **Required tests** section — status lifecycle transitions, expiry on read, transient errors
  leaving status unchanged, label rules (case-insensitive duplicate), cap, replace with
  different identity, cross-user isolation, cascade on user delete.
