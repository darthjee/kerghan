# Rewrite sync.md

Rewrite `docs/agents/specs/issues/sync.md` around the issue's Solution, keeping its header ("Part of the Issues and Projects specs") and its existing settled bullets where still true (ids only, Unavailable vs Unknown gating, deleted project or user is a no-op, owner's integrations, gone links get no marker, addressing by owner/name).

Sections, in order (each a `##` mirroring the issue's `###` subsection):

1. **Fields and ownership** — title, body, state two-way; `state_reason` never sent (accepted loss, settles `model.md` row 15 / E55); diff-only `PATCH`; verbatim values with blank body to `NULL` and `NULL` equal to `''` (this is the normalization invariant `github-link.md` defers to #488).
2. **Reconcile** — the one algorithm: read marker (`R`, `Tm`) and base, conditional `GET` first, the L/B/G per-field table with the E7 tie to Kerghan, diff `PATCH`, one commit in lock order with compare-and-clear, the revision-changed rule (skip pulled fields entirely, re-enqueue), ping-pong (E11), ETag from `GET` only and `NULL` after a `PATCH`.
3. **Triggers** — T1 to T6 table (edit after commit with no dedupe, single-issue refresh, project refresh oldest `last_synced_at` first, retry sync, boot, compare-and-clear miss); no trigger for link creation, unlink, gone, repository change or integration fixes; **no approval trigger** (E24: `denied` is final, markers stay until user deletion, a future un-deny must re-enqueue).
4. **Job** — one `issues.reconcile`, params `{ linkId }`, registered on Issues module init with the sync service as attribute; the outcome-to-job mapping table (`done`, `requeue`, `stopped`, `transient`, `rate_limited`); the job's own attempt counter and `lastAttempt`; the five guards in order (link live and not gone, owner approved, repository not Unavailable, a candidate integration resolves, a candidate not paused); idempotence; log fields allowlist.
5. **Rate limits** — `resetAt` from the client, 60 s fallback when `null`; pause per integration id; waiting set plus one timer per integration (injected `Clock`/scheduler), oldest marker first; waits never consume retries (E17); derived "rate limited until X"; lost on restart; no write pacing in v1.
6. **Retries and `sync_failed`** — `maxRetries` 5 and cooldown 30 s via class getters, read from `KERGHAN_ISSUES_SYNC_MAX_RETRIES` and `KERGHAN_ISSUES_SYNC_COOLDOWN_MS` (positive integers, fallback to defaults); the four reasons table with when each is set (including E22 access loss mapped to `forbidden` / `credential_invalid`); the exits (clearing push, refresh with no marker, retry sync resetting to `linked` at once, `gone`); `sync_failed` never blocks a job.
7. **Staleness** — `last_synced_at` set by every successful reconcile and by link creation; derived `stale` after `KERGHAN_ISSUES_SYNC_STALE_AFTER_SECONDS` (default 3600); display only, no read enqueues; T2/T3 skip marker-less links synced under 60 s ago ("already fresh").
8. **Integration selection** — candidates (usable and listing the repository in `repositories_sources`, through Repositories' exported service; handle-only is not a candidate), none-found reasons, order (PAT and OAuth app before GitHub App, oldest first), fallback on credential failures only restarting from the `GET`, aggregate reason, paused candidates skipped, E22 probe on the same candidate.
9. **Marker lifecycle** — creation for `linked` and `sync_failed` links, timestamps from `Clock`, commit guard, compare-and-clear miss re-read, boot enqueues all, never expires, several instances.
10. **GitHub issue client operations** — the `getIssue` / `updateIssue` / `probeIssues` table on `IntegrationsGithubService`, `RepoFailure` shared kinds, `forbidden` as its own kind, `renamed` adapter-internal with a `renamedTo` hint, `changes` never carrying `state_reason`.
11. **Configuration** — the three keys with defaults and validation, and the note that the implementation issue documents them in `environment-variables.md` and the job in `modules/workers.md` when the code reads them (see plan Notes).
12. **Alternatives considered** — collect the rejected options from the dialogue: blind `PATCH`; separate push and refresh jobs; full `PATCH`; storing `state_reason`; CRLF normalization; `exhausted()` from the library or marking on every failure; per-user pause; per-job timers; no auto-resume; write pacing; engine-default retries; an `access_lost` reason; keeping `sync_failed` until success on retry; auto-refresh on open; a project refresh `429` cooldown; any-usable-integration candidates; no fallback; boot filtering; marker expiry; an approval listener.
13. **Open questions** — none owned by #488; keep only items owned elsewhere (routes and payloads #489, wording #491, GitHub App write permission #490, per-field timestamps with no owner).
14. **Required tests** — rewrite to match the rules: one bullet per rule group, with tiers per `testing.md` (unit for the reconcile table and guards, `(engine)` for retry, exhaustion via the job's counter and the issues retry config, `(race)` for E10/E41/E44/E13/E15 and the compare-and-clear miss re-read, `(db)` for boot re-enqueue), plus: rate-limit waiting set and timer with `FakeClock` (no call while paused, one enqueue per link at reset, never `sync_failed`); fallback order and aggregate reason; each `sync_failed` set and exit path; retry sync resetting the status; stale flag and the 60 s fresh skip; diff-only `PATCH` never carrying `state_reason`; `NULL`/`''` equality; ETag cleared after a `PATCH`; non-approved user makes no call and no listener exists; params ids-only and the canary sweep.
