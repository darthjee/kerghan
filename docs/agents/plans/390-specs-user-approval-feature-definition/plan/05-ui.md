# ui.md

Define the frontend behavior in `docs/agents/specs/user-approval/ui.md`.

**User side (#392):**

- Auth state gains `pending`, set from `status.json`'s `status: "pending"` and carried on the
  `AuthEvents` bus next to `loggedIn` / `isAdmin`.
- After register and login the frontend re-checks `status.json` instead of assuming logged-in
  (today `RegisterController` emits logged-in and redirects home).
- Full-page "Awaiting approval" view replaces the app content while pending, with "Check again"
  and "Log out"; the header shows no logged-in menu.
- Approval picked up by re-checking on window focus and on "Check again"; no timer polling.
- Login modal shows an explicit message on `403 USER_DENIED` (e.g. "This account has been denied
  access.").

**Admin side (#393):**

- On the existing admin users page (`frontend/assets/js/components/resources/admin/`), a status
  filter (including a pending view) and the status of each user.
- Approve (shown only for pending users) and deny / ban actions, with the `422` / `409` errors
  surfaced to the admin; no action offered on the admin's own row or on the default user where
  the API would refuse it.

**Required tests:** pending state on the bus, re-check after register / login, awaiting view
rendering and its actions, focus re-check, denied login message, admin filter, approve / deny
actions and error display.
