# Add the "Standalone" section to environment-variables.md

Add a "## 5. Standalone (`darthjee/kerghan-standalone`)" section before "Keeping this doc honest".
Build it from `specs/standalone/variables.md`, checked against the allowlist actually written in
`standalone/vault/docker-compose.yml`:

- **How values flow**: `~/.kerghan/kerghan.env` (or `-e` / `--env-file` on `docker run`), then
  the Vault container environment, then interpolation in the inner compose file, then each
  service. No secret is baked into the image.
- **Contract table**, one row per group: required secrets (`KERGHAN_SECRET_KEY`,
  `KERGHAN_INTEGRATIONS_KEY`, generated by the client on the first `up`); internal values fixed by
  the stack; the overridable `KERGHAN_MYSQL_PASSWORD` (fixed when the volume is created);
  optional pass-through (the allowlist, listed by name as shipped); standalone/Vault-level
  (`VAULT_DOCKERD_TIMEOUT`, `COMPOSE_UP_ARGS`, host port); excluded (`KERGHAN_EMAIL_*`,
  `KERGHAN_DEMO_PASSWORD`).
- A variable not on the allowlist never reaches the backend, and a new backend variable must be
  added to the allowlist to pass through.
- **`FRONTEND_BASE_URL`**: the client default, what plain `docker run` users must set, and that
  an `https` URL (a TLS reverse proxy) is needed for the GitHub OAuth App / GitHub App types.

Also add the new section to any table of contents or intro list in the file, and link to
`standalone.md` for the client and `~/.kerghan/` layout.
