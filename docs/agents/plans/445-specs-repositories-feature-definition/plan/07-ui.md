# ui.md

Create `docs/agents/specs/repos/ui.md`, pointing at existing frontend conventions only as precedent (hash routes in `frontend/assets/js/utils/routing/HashRouteResolver.js`, navbar in `frontend/assets/js/components/common/header/helpers/HeaderHelper.jsx`, the Integrations page under `frontend/assets/js/components/resources/accounts/pages/`).

Decided:

- **Placement:** a top-level **Repositories** navbar link to `#/repositories`, shown to every logged-in user, hidden while the account awaits approval.
- **Table:** `owner/name` linking to GitHub; public/private badge; source badges (integration labels and/or "public"); status (Added / Not added / Unavailable / Unknown); **Add** on not-added rows (spinner, row turns Added, inline error e.g. on `404`).
- **Toolbar:** filter (All by default / Added / Not added / Unavailable), name search, **Refresh**, "last synced X ago"; pagination controls under the table.
- **Sync UX:** stored rows shown immediately with a "Syncing with GitHub…" indicator; reload when the sync ends; full spinner only on the very first sync.
- **Source errors:** a dismissible banner per failed source, linking to the Integrations page.
- **Empty state:** no handle and no integration → explain both options, link to Account and Integrations.
- **GitHub handle field** on the Account page (`#/account/my-account`), editable by the default user too.
- The frontend never calls GitHub for this feature.

Open markers: Refresh-cooldown (`429`) message and polling interval (#446/#447); handle field validation messages (#449); UI edge cases (#450); frontend specs (#451).

End with **Required tests** for the decided UI states.
