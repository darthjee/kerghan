# Issues and Projects — API

Decided. Part of the [Issues and Projects specs](../issues.md).

The Issues and Projects API: routes, payloads, error codes, pagination, validation and how sync state is exposed. It is built by the implementation issue (#492) with no decisions of its own; wording, screens and polling cadence are in [ui.md](ui.md).

## Every route

Copied from [`routes/repositories.md`](../../backend/routes/repositories.md#every-route) unless stated:

- **Every route is `POST` and ends in `.json`, reads included.** Tent's cache key ignores the method, so a user-scoped `GET` risks being cached for everyone. No Issues route answers `GET`.
- **Actions are verb suffixes**, single reads included (`…/show.json`, `…/edit.json`, `…/delete.json`, `…/unlink.json`), as Auth, Sessions and Admin already do. There is no `PATCH`/`DELETE`, so the unlink confirmation never travels in a `DELETE` body. A bare `/:id.json` read is avoided because it would collide with `/projects/mine.json`.
- **Ids in the path.** Projects and issues are named by their public uuid in the path (no dot clash, unlike repository names); see [Exposed identifiers](#exposed-identifiers). The body carries only the payload.
- **Issue routes are fully nested under their project:** `/projects/:projectId/issues/:issueId/...`. The service looks the issue up **within** the path's project through the single access check. An issue of another project, or of another user's or a deleted project, answers the same `404` as a missing one.
- **Malformed path ids** (not a uuid, checked with `ParseUUIDPipe` as Sessions does) answer `400 VALIDATION_FAILED`. Well-formed ids that do not resolve answer `404`.
- **Auth, CSRF and cache:** global `JwtGuard` (no `@Public()`, no `@AdminOnly()`), the caller from `req.user.sub`; `OriginGuard` covers every route; cache class `user-scoped` (`@CachePolicy(CacheClass.UserScoped)`), so every response that passes the guards (successes and handler errors) sends `X-Skip-Cache: true` and `Cache-Control: no-store`. Navi warms nothing.
- **Bodies** go through the global `ValidationPipe({ whitelist: true, transform: true })`: unknown properties are stripped and ignored.
- **Errors** use the standard error shape (`core/http-exception.filter.ts`), with `retryAfterSeconds` in both the body and `Retry-After` when there is a delay.
- **Admins** have no access to anyone's projects or issues.
- Controllers stay thin: validation in DTOs, everything else in the `issues` module's services.

```text
POST /projects/mine.json
POST /projects/create.json
POST /projects/from-repository.json
POST /projects/:projectId/show.json
POST /projects/:projectId/edit.json
POST /projects/:projectId/repository.json
POST /projects/:projectId/delete.json
POST /projects/:projectId/refresh.json
POST /projects/:projectId/issues.json
POST /projects/:projectId/issues/create.json
POST /projects/:projectId/issues/import.json
POST /projects/:projectId/issues/:issueId/show.json
POST /projects/:projectId/issues/:issueId/edit.json
POST /projects/:projectId/issues/:issueId/delete.json
POST /projects/:projectId/issues/:issueId/attach.json
POST /projects/:projectId/issues/:issueId/unlink.json
POST /projects/:projectId/issues/:issueId/refresh.json
POST /projects/:projectId/issues/:issueId/retry-sync.json
```

That is the complete list: 18 routes.

## Exposed identifiers

- **Projects and issues expose a uuid, never their internal `int` id**, following Integrations and Sessions. `issues_projects` and `issues` each have a `uuid` column ([model.md](model.md)): `char(36)`, generated by the application with `randomUUID()` at insert, unique indexes `idx_issues_projects_uuid` and `idx_issues_uuid`. The API calls it `id`, as Integrations does.
- The internal ids stay internal: foreign keys, job params (`{ linkId }`), logs and locks keep using them. Sequential ids would leak the global creation rate and break the codebase's "no internal id in responses" rule.
- No human-friendly issue reference (per-project number) in v1.
- **A repository is named by the existing repo ref** of [`routes/repositories.md`](../../backend/routes/repositories/identity-and-sync.md#repo-ref): exactly one of `{ githubId }` or `{ fullName }` with the same validation (`400` on both or neither, or malformed), resolved case-insensitively among the caller's own rows with the same `fullName` tie-break. Used by explicit create, the shortcut and the repository route. A ref not among the caller's rows answers `404`, like Add. A row that exists but is not added answers `409 PROJECT_REPOSITORY_NOT_ADDED`, so a rejected ref never reveals more than Add does.
- **Responses never contain:** the internal `id` of a project, issue, repository, link or marker; any `user_id`; an internal `integrations.id` or any integration field (the "rate limited until X" state carries only the time); credential material.
- **Repository summary in project responses:** `githubId`, `owner`, `name`, `fullName`, `private` and `status` (`added`, `unavailable`, `unknown`), the same names as the Repositories listing row. A dangling reference reads `unavailable` with the snapshot fields `null`.
- **GitHub side of a link:** its `number` and a `url` built from the repository's stored `owner`/`name` and the number. GitHub's global issue id is not exposed in v1.

## Required tests

Default tier: e2e with fakes ([testing.md](testing.md#default-tier-by-category)); races are `(db)`.

- **Route access matrix** ([testing.md](testing.md#security-verification)), complete against the 18 registered routes: every route answers `401` without a session, runs `OriginGuard`, sends `X-Skip-Cache: true` and `Cache-Control: no-store` on success and on handler errors, declares `user-scoped`, and answers no `GET`. Another user's or a deleted project, and an issue of another project, answer `404`; malformed uuids answer `400`.
- No response contains an internal id, `user_id`, an integration field or credential material; `error.meta` carries only uuids, counts, field names, timestamps or reasons.
- Every project, issue, link and trigger outcome and every code of the catalogue, including the project creation paths (`200`/`201`/`409`), the creation and repository-change races `(db)`, repository change or detach answering `409 PROJECT_HAS_LINKS` with the link count only while links exist and succeeding at zero, the attach stale confirmation within the same second (`datetime(3)`), a repeat unlink answering `ISSUE_NOT_LINKED`, delete refused while linked and the attach/delete race `(db)` (E61 to E64 of [edge-cases.md](edge-cases.md)).
- Listing defaults, bounds, sort, filters, literal search and totals; issue rows without `body`.
- The link object: `states` precedence, `linked` alone, `reason`, `rateLimitedUntil`, `stale` never for `gone`; reads never enqueue.
- T2 `202`/`200 alreadyFresh`, T3 counts, T4 reset and no-op, the refusals, and retry refused while Unavailable keeping the reason.
- The four codes of #490 (`PROJECTS_LIMIT_REACHED`, `ISSUES_LIMIT_REACHED`, `ISSUE_LINK_RATE_LIMITED`, `ISSUE_EDIT_RATE_LIMITED`) at their place in the order of checks, with the cases of [security.md](security.md#required-tests).
- Validation: strict types, code-point lengths with a 4-byte character, trimming rules, `null` handling, `number` bounds.
